# Frontend

Scope: how browser UI is built in Agent Starter. Repository layout and package scripts belong in [structure-and-toolchain.md](structure-and-toolchain.md). Verification belongs in [verification-and-evidence.md](verification-and-evidence.md) and [testing-and-fixtures.md](testing-and-fixtures.md).

Detailed client procedures live under [`apps/client/.agents/rules/`](../../apps/client/.agents/rules/) and are loaded by [`apps/client/AGENTS.md`](../../apps/client/AGENTS.md). That folder is the single source of truth for feature order, modules, pages, routing, styling, tables, performance, debugging and store-integration testing. This domain rule states reviewable invariants only.

- **FE-01** The hosted SPA lives in `apps/client`. Shared primitives belong to `@agent-starter/design-system`. Shared Redux-first form and router runtimes belong to `packages/redux-form` and `packages/redux-router` (`typed-redux-router`). Do not introduce a second client router, a second design kit, or a parallel form state library for product UI.
- **FE-02** Meaningful application-observable UI state lives in Redux. React is presentation: subscribe narrowly, dispatch intents and render. Ephemeral interaction-only state (hover, focus, pointer position, animation frames) may stay local. Do not move forms, modals, route state, filters, drafts or workflow eligibility into React-local state.
- **FE-03** Feature work order is fixed: Redux behaviour first, Node-only store integration tests next, React last. Bug fixes start the same way unless the defect is obviously presentational. Confidence for behaviour is the store harness suite, not React unit tests or browser e2e for application logic.
- **FE-04** Organise client code by business module under `src/modules/<name>/` with a Redux side and a React side (`redux.ts` / `react.tsx`, or folders when a module has several slices/screens). Primitives stay in the design system; repeated presentation without domain ownership stays in `src/shared/components/`. Cross-module imports use explicit public contracts, never another module's private files.
- **FE-05** The client is a SPA. In-app navigation goes through the Redux router (`typed-redux-router`). Keep the route tree data-only; map route names to pages in `src/pages.ts`. Do not assign `window.location` or use React Router / Next Link for product routes.
- **FE-06** Every product styling choice uses a CSS custom property. Consume public `--ui-*` tokens from `@agent-starter/design-system`; put product CSS in `@layer app`; put named visual packs in `@layer themes`. Do not copy token literals, consume private `--_ui-*` properties or bypass layer order with unlayered CSS / `!important` for theming. Do not set `--ui-*` (or other product styling) through React `style`; override hooks on a class in `@layer app`.
- **FE-07** Client HTTP talks to same-origin session APIs (mock or real). The browser must not hold organisation secrets or staff bypasses. Retries preserve operation IDs and must not duplicate management mutations.
- **FE-08** Client store integration tests run in Node against the real production store and router (`browser: null`), with HTTP at the real client boundary (for example Nock). React stays on unit tests only. Naming and commands are owned by `apps/client/.agents/rules/testing.md`.
- **FE-09** Library packages (`design-system`, `redux-form`, `redux-router`, `live`) keep their own package AGENTS/docs for package-local contracts. Product composition, module ownership and client verification remain under this domain and `apps/client/.agents/rules/`.
- **FE-10** Client error copy is qualitative and journey-specific. Map failures through `appFailure` and `liveQueryFailureMessage` (see `apps/client/.agents/rules/errors.md` and `user-facing-error.ts`). Do not bind thrown messages, problem codes, or live socket labels directly into UI state or components.
- **FE-11** Route admission uses catalogue/list live evidence; detail live scopes are for page rendering, not router commit. Procedure and resource table: `apps/client/.agents/rules/navigation-admission.md`.
- **FE-12** Client feature effects are module-owned: thunks for async work, listener middleware exported by the module for reactions. `apps/client/src/store.ts` composes reducers and middleware only; it must not define thunks or register listeners. Procedure: `apps/client/.agents/rules/modules.md`; lint: `check-modular-effects.mjs`.

Review evidence: name the FE invariant, the owning module or package, and the concrete bypass (second router, React-owned workflow state, untokenised styling, missing store harness proof or authority leak into the browser). Prefer the smallest correction that restores the Redux-first and design-system boundaries.
